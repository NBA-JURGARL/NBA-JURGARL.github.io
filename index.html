Comment le SIEM Wazuh a été déployé

Étape 1 sur 5

  1. 4 sites, ~200 postes

    Des postes répartis sur quatre sites, à superviser depuis un point central.

  2. Déploiement par le RMM

    L'agent Wazuh est installé sur chaque poste via NinjaOne.

  3. Remontée via le WAN

    Les agents distants envoient leurs événements au serveur à travers le WAN.

  4. Serveur sur vSphere/vSAN

    Le serveur Wazuh tourne en machine virtuelle sur l'infrastructure vSphere/vSAN.

  5. Vulnérabilités et alertes

    Les vulnérabilités remontent et les alertes sont triées.

Ce site

Un portfolio orienté sécurité doit être propre lui-même. Voici ce qui est en place.

  • Content-Security-Policy stricte : uniquement des ressources du site, aucun script ni style écrit dans le HTML.
  • Aucune ressource tierce : polices et scripts hébergés sur le site. Aucun cookie, aucun traceur, aucune mesure d'audience.
  • Fichier security.txt (RFC 9116) pour signaler une vulnérabilité.
  • Photo débarrassée de ses métadonnées (EXIF, GPS).
  • HTML et CSS écrits à la main, sans framework ni étape de build. Code source public sur GitHub.
